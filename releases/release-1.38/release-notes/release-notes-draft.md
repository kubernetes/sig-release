### API Change

- Added Beta support for requesting Pod certificates signed with ML-DSA keys, behind the `PodCertificateMLDSA` feature gate. The PodCertificateRequest API and the `podCertificate` projected volume source accept the MLDSA44, MLDSA65, and MLDSA87 key types. ([#142108](https://github.com/kubernetes/kubernetes/pull/142108), [@everettraven](https://github.com/everettraven)) [SIG API Machinery, Apps, Auth, Autoscaling, Node and Scheduling]
- Added `resource.MaxMilliQuantity()`, which returns the largest quantity whose `MilliValue()` and `ScaledValue(resource.Milli)` do not overflow an int64. For a non-negative quantity, compare it against this bound with `Quantity.Cmp` before calling `MilliValue()` or `ScaledValue(resource.Milli)`. ([#140674](https://github.com/kubernetes/kubernetes/pull/140674), [@thc1006](https://github.com/thc1006))
- Added `resourceVersion` to delete responses, so clients can track the version at which an object was deleted. The value is either the revision of the delete itself or a later revision at which the object was already observed as deleted. ([#138724](https://github.com/kubernetes/kubernetes/pull/138724), [@michaelasp](https://github.com/michaelasp)) [SIG API Machinery, Apps, Auth, Etcd, Node, Scheduling and Testing]
- Added support for PKCS#10 signing requests signed with ML-DSA (post-quantum) keys in the CertificateSigningRequest API, behind the `CertificateSigningRequestMLDSA` feature gate. ([#142196](https://github.com/kubernetes/kubernetes/pull/142196), [@everettraven](https://github.com/everettraven)) [SIG API Machinery, Apps and Auth]
- Added the `AsScaledInt64` and `AsMilliInt64` methods to `resource.Quantity`, which report int64 overflow with a boolean. The `Value`, `MilliValue`, and `ScaledValue` methods saturate to `math.MinInt64` or `math.MaxInt64` on overflow instead of returning a wrapped value. As a result, a `kubelet` CPU reservation no longer wraps to a negative value when the configured quantity exceeds that range. ([#141305](https://github.com/kubernetes/kubernetes/pull/141305), [@thc1006](https://github.com/thc1006)) [SIG API Machinery and Node]
- Added the `clientCertificateKeyAlgorithm` and `serverCertificateKeyAlgorithm` fields to `KubeletConfiguration`, so the `kubelet` can request client and server certificates with ECDSA, RSA, or ML-DSA keys. The default remains ECDSA-P256. ([#142046](https://github.com/kubernetes/kubernetes/pull/142046), [@rphillips](https://github.com/rphillips)) [SIG API Machinery, Auth, Node and Scheduling]
- Changed `resource.Quantity` so that calling `String` or encoding a quantity no longer mutates the instance, which it previously did in some cases. If an instance needs its string representation multiple times, call `CacheString` to pre-populate the value while the caller owns the instance and can safely mutate it. This is only needed for instances not created by `ParseQuantity`, such as those built directly or modified through math operations. ([#142277](https://github.com/kubernetes/kubernetes/pull/142277), [@pohly](https://github.com/pohly))
- Changed the CompositePodGroup `spec.schedulingPolicy.gang.minGroupCount` field to be mutable. When it decreases, `kube-scheduler` re-enqueues the affected Pods. ([#141023](https://github.com/kubernetes/kubernetes/pull/141023), [@jdzikowski](https://github.com/jdzikowski)) [SIG API Machinery, Scheduling and Testing]
- Changed the error returned when an update clears the Node `spec.podCIDRs` field to `field cannot be cleared once set`, replacing `node updates may not change podCIDR except from "" to valid`. ([#141260](https://github.com/kubernetes/kubernetes/pull/141260), [@krishhna24](https://github.com/krishhna24)) [SIG API Machinery, Apps and Testing]
- Changed topology-aware scheduling (TAS) in `kube-scheduler` to respect `nominatedNodeName` when selecting a placement. This does not apply to PodGroups that belong to a CompositePodGroup ([#140863](https://github.com/kubernetes/kubernetes/issues/140863)). ([#139472](https://github.com/kubernetes/kubernetes/pull/139472), [@mboersma](https://github.com/mboersma)) [SIG API Machinery, Scheduling and Testing]
- Exposed PlacementFeasible as an extension point in `kube-scheduler`, so out-of-tree plugins can evaluate whether a PodGroup placement is feasible. ([#141314](https://github.com/kubernetes/kubernetes/pull/141314), [@macsko](https://github.com/macsko))
- Fixed CRD validation failures for `minItems` and `minProperties` reporting the misleading `Invalid value: <count>` instead of `Too few: <count>: must have at least N items`. ([#141641](https://github.com/kubernetes/kubernetes/pull/141641), [@yongruilin](https://github.com/yongruilin))
- Fixed the DefaultPreemption plugin in `kube-scheduler` returning an error when a filter extender rejected a Pod. Such nodes are passed to preemption-capable scheduler extenders as candidates with empty victim lists, so those extenders must handle candidates that have no victims. ([#135486](https://github.com/kubernetes/kubernetes/pull/135486), [@FouoF](https://github.com/FouoF))
- Fixed the OpenAPI schema for ValidatingAdmissionPolicyBinding and MutatingAdmissionPolicyBinding to mark `spec.paramRef.parameterNotFoundAction` as required, matching existing API server validation. Client-side validators, for example kubeconform, can catch the missing field before apply. ([#141527](https://github.com/kubernetes/kubernetes/pull/141527), [@grosser](https://github.com/grosser))
- Removed locked GA feature gates `CustomResourceFieldSelectors` and `CRDValidationRatcheting`. ([#141207](https://github.com/kubernetes/kubernetes/pull/141207), [@Jefftree](https://github.com/Jefftree)) [SIG API Machinery and Testing]
- Removed the `DynamicResourceAllocation` feature gate, which has been GA and locked to enabled since `v1.35`. Dynamic resource allocation is always enabled. ([#141946](https://github.com/kubernetes/kubernetes/pull/141946), [@troychiu](https://github.com/troychiu)) [SIG API Machinery, Apps, Auth, Node, Scheduling and Testing]

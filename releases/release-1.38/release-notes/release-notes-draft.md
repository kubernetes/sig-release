## Urgent Upgrade Notes 

### (No, really, you MUST read this before you upgrade)

- ACTION REQUIRED: Changed `kubelet` to reject env-file entries with a hash immediately after a closing single quote, such as `KEY='value'#suffix`, instead of silently ignoring the suffix. Add a space or tab before an intended comment, or move an intended literal suffix inside the single quotes. Affected containers may fail to start until these entries are corrected. ([#143221](https://github.com/kubernetes/kubernetes/pull/143221), [@rishabhraj1572](https://github.com/rishabhraj1572))
 - ACTION REQUIRED: Changed the `PodNominator.NominatedPodsForNode` method in the `kube-scheduler` framework to take a `klog.Logger` as its first argument. Out-of-tree scheduler plugins that call this method must pass a logger. ([#142118](https://github.com/kubernetes/kubernetes/pull/142118), [@jdzikowski](https://github.com/jdzikowski)) [SIG Scheduling and Testing]
 - ACTION REQUIRED: Fixed several bugs in the ID range handling for Pods using user namespaces (`spec.hostUsers: false`). Before upgrading the `kubelet`:
  
  - If the subordinate ID range for the `kubelet` user in `/etc/subuid` and `/etc/subgid` ends at or past 4294967295, for example `kubelet:65536:4294901760`, reduce the count by at least one `idsPerPod` (65536 by default). Such a range contains an ID the kernel can't map, and the `kubelet` refuses to start with it.
  - Delete any Pod stuck in `ContainerCreating` with a `FailedCreatePodSandBox` event, or drain the node. An earlier `kubelet` may have assigned such a Pod the invalid range, and the upgraded `kubelet` refuses to start with `create user namespace manager: record pod mappings for existing pod "<uid>": id 4294901760 is out of range`.
  
  The `kubelet` also no longer fails to start when the `kubelet` user exists but the `getsubids` binary is not installed; it falls back to the default ID range, as documented. Pods are no longer assigned the ID range ending at 4294967295 (2^32-1), which the kernel refuses to map, so the default range ends one `idsPerPod` block lower. ([#141345](https://github.com/kubernetes/kubernetes/pull/141345), [@halaney](https://github.com/halaney))
 - ACTION REQUIRED: Removed the `SeparateTaintEvictionController` feature gate from `kube-controller-manager`. Remove this gate from any `--feature-gates` configuration before upgrading. The standalone taint eviction controller always handles taint-based eviction, and you can still disable it with `--controllers=-taint-eviction-controller`. ([#141789](https://github.com/kubernetes/kubernetes/pull/141789), [@wasylkowski-a](https://github.com/wasylkowski-a)) [SIG API Machinery, Apps, Node, Scheduling and Testing]
 - ACTION REQUIRED: Renamed the `type` label on the Alpha metrics `scheduler_queued_entities` and `scheduler_queue_incoming_entities_total` to `entity`. Update monitoring dashboards and alerts that filter on `type`. ([#143180](https://github.com/kubernetes/kubernetes/pull/143180), [@dom4ha](https://github.com/dom4ha)) [SIG Instrumentation and Scheduling]
 - Removed the `PodSchedulingReadiness` feature gate from `kube-scheduler` and related components as the feature is permanently enabled. ([#141741](https://github.com/kubernetes/kubernetes/pull/141741), [@wasylkowski-a](https://github.com/wasylkowski-a)) [SIG Scheduling]
